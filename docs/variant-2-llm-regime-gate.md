# 변형 2 — LLM 레짐 게이트 (창의성 점수 겨냥)

## 왜 이 변형인가

원 ATR 문서도, 변형 1도, 레짐 판정이 전부 ADX/EMA 같은 결정론적 규칙이다. AlphaBot 조사에서
확인했듯 이런 규칙기반 전략은 "AI 트레이딩 해커톤" 심사에서 창의성 점수가 약하다 — 룰 하나
바꾼다고 "AI 로직"이라 부르기 애매하다. 이 변형은 변형 1의 실행 골격(리스크게이트·주문경로)은
그대로 두고, **레짐 판정 위에 LLM 컨텍스트 게이트 한 겹**만 얹는다.

## 구조

변형 1의 `decide_for_symbol()` 파이프라인에 삽입 지점 하나 추가:

```
ADX/EMA 기술적 레짐 (변형 1 그대로)
        ↓
매크로 stage 게이트 (regime-signals, 변형 1 그대로)
        ↓
[신규] LLM 컨텍스트 게이트 ← 오늘의 뉴스 헤드라인·VIX 기간구조·경제캘린더를
        │                    읽고 "이 레짐 판정을 신뢰해도 되는가"를 판단
        ↓
주문 intent 생성
```

LLM은 **레짐을 새로 판정하지 않는다** — 이미 계산된 기술적 레짐을 무시할지(스킵) 말지만
결정한다(veto-only, 이진 게이트). 이유: LLM이 델타·행사가 선정 같은 정밀 계산까지 하게 하면
할루시네이션 리스크가 사이징 오류로 직결된다. LLM의 역할은 "숫자로 못 잡는 맥락"(예: "오늘
CPI 발표 30분 전인데 헤드라인 톤이 이례적으로 긴장돼 있다" 같은)만 담당한다.

## 프롬프트 스케치

```
입력: {symbol, regime, adx, atr, macro_stage, 최근 24시간 관련 헤드라인 5개, VIX, 다음 경제지표 발표까지 남은 시간}
출력: {proceed: bool, reason: str}  ← 구조화 출력, 자유서술 금지(사이징에 안 쓰이므로 안전)
```

## 리스크

- LLM 호출이 사이클마다 추가 지연·비용 발생 — 대회 8일 안에는 심각한 리스크 아님(체결 사이클이
  분 단위면 충분한 여유).
- **LLM이 게이트를 열든 닫든 리스크게이트(사이징·킬스위치)는 절대 안 거친다** — LLM 판단은
  진입 여부만 건드리지, 이미 계산된 정의된위험·계약수·손절선은 절대 재계산하지 않는다(이게
  깨지면 창의성 점수보다 안전성이 먼저 무너진다).

## 8일 빌드 관점

변형 1이 완성된 뒤에 붙이는 **애드온**이다 — 변형 1 없이 이것부터 만들면 실행경로가 없어서
테스트를 못 한다. 우선순위 2순위(제가 먼저 드린 순서)와 정확히 일치.
